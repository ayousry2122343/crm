================================================================
  Phase 2 — المطلوب تنفيذه (~8 sprints)
================================================================

## Sprint 6: Products + Pricebooks
- Product model (name, SKU, description, unitPrice, currency, isActive, bilingual labels)
- ProductCategory model
- Pricebook model (name, isDefault, currency) + PricebookEntry (productId, pricebookId, unitPrice, minQty)
- Product CRUD API + controller
- Product admin UI (DataTable + create/edit dialog)
- Pricebook admin UI
- Tests (TDD)

## Sprint 7: Quotes / Proposals
- Quote model (dealId, contactId, status: DRAFT/SENT/ACCEPTED/REJECTED/EXPIRED, validUntil, subtotal, discount, tax, total)
- QuoteLineItem model (quoteId, productId, quantity, unitPrice, discount, total)
- Quote PDF generation (using pdfmake or @react-pdf — no external API)
- Quote API: CRUD + send (email with PDF attachment) + accept/reject endpoints
- Quote Builder UI (line items table, totals, discount, tax calc, PDF preview)
- QuoteDetail view with status timeline
- "Create Quote" button on DealDetail
- Tests (TDD)

## Sprint 8: Email Marketing — Campaigns
- Campaign model (name, subject, body, status: DRAFT/SCHEDULED/SENDING/SENT/PAUSED, listId, scheduledAt, sentAt, stats JSON)
- CampaignRecipient model (campaignId, personId, status: PENDING/SENT/OPENED/CLICKED/BOUNCED/UNSUBSCRIBED)
- Campaign API: CRUD + schedule + send (BullMQ job — batch send with rate limiting)
- Open/click tracking (tracking pixel + redirect links)
- Unsubscribe mechanism (token-based link + Person.unsubscribed flag)
- Campaign Builder UI (template editor, list selector, schedule picker, stats dashboard)
- Tests (TDD)

## Sprint 9: Drip Sequences
- Sequence model (name, triggerEvent, steps JSON array)
- SequenceStep: {delay (hours/days), action (send_email/update_field/notify), templateId, conditions}
- SequenceEnrollment model (sequenceId, personId, currentStep, status: ACTIVE/COMPLETED/PAUSED/EXITED)
- Drip engine: BullMQ delayed jobs — schedule next step on enrollment, process step, advance or exit
- Exit conditions (person replies, deal created, manual exit, field changed)
- Sequence Builder UI (visual step list — add/remove/reorder steps, delay config, condition editor)
- Enrollment UI on PersonDetail (enroll/pause/exit)
- Tests (TDD)

## Sprint 10: Time-based Workflow Triggers + Cron
- Extend Workflow model: add triggerType 'SCHEDULED' + cronExpression + lastRunAt
- CronRunner service: BullMQ repeatable job that evaluates cron workflows every minute
- Query builder for scheduled triggers: "deals where expectedClose < today AND status = OPEN"
- UI: add 'Scheduled' trigger type in WorkflowEditor with cron expression builder (or simple interval picker: daily/weekly/monthly + time)
- Deal rotting automation: "if deal in stage X for > 7 days, notify owner"
- Tests (TDD)

## Sprint 11: Two-way Email Sync
- EmailAccount model (userId, provider: GMAIL/OUTLOOK, credentials (encrypted), syncState, lastSyncAt)
- Gmail OAuth 2.0 flow (consent screen + callback + token storage)
- Microsoft Graph OAuth flow (same pattern)
- Email sync worker (BullMQ): pull inbox/sent via IMAP or API, match to Person by email, store as Activity type=EMAIL
- EmailThread model (accountId, threadId, subject, lastMessageAt, personId)
- EmailMessage model (threadId, messageId, from, to, subject, body, direction: IN/OUT, receivedAt)
- Email tab on PersonDetail: show threaded conversations
- Settings page: connect/disconnect email accounts
- Tests (TDD)
- ⚠️ ملحوظة: Gmail OAuth محتاج Google Cloud Console project + OAuth consent screen. Microsoft محتاج Azure AD app registration. الـ implementation هيكون جاهز بس التفعيل محتاج credentials.

## Sprint 12: Copilot Sidebar (RAG)
- Copilot API: POST /api/v1/ai/copilot/chat with {message, context: {entityType, entityId}}
- RAG pipeline: query pgvector for relevant embeddings → build context → call Ollama chat
- Copilot sidebar component (slide-out panel, chat interface, streaming responses)
- Context-aware: knows which page/record the user is viewing
- Suggested prompts: "Summarize this deal", "Draft follow-up email", "What's the history with this contact?"
- BullMQ embedding worker: auto-embed on Person/Deal/Activity create/update (wire up the existing EmbeddingsService)
- Tests (TDD)

## Sprint 13: Customer Portal
- Portal model (workspaceId, domain, theme, enabled)
- PortalUser model (personId, email, passwordHash — separate from internal User)
- Portal auth (separate JWT issuer, portal-scoped guards)
- Portal API: view own deals + quotes + activities + submitted forms
- Portal frontend (separate Vue app or route group — light PrimeVue theme)
- Portal pages: Dashboard, My Deals, My Quotes (accept/reject), My Activities, Profile
- Settings: enable/disable portal, customize branding
- Tests (TDD)

## Sprint 14: Blog + Phase 2 Closeout
- Blog model (title, slug, body (markdown), author, status: DRAFT/PUBLISHED, publishedAt, tags, metaDescription)
- BlogCategory model
- Markdown-to-HTML rendering (marked or markdown-it)
- Blog pages on website: /blog, /blog/:slug
- Blog admin in dashboard: CRUD + markdown editor + image upload (MinIO)
- SEO: meta tags, og:image, sitemap.xml generation
- Phase 2 closeout: full test suite run, e2e, tag v2.0.0
